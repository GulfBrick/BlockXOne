# Phase 7 Plan 01: Split Investor And Operator Surfaces Without Breaking Live Role Flows

## Objective

- **What:** Replace the mixed landing and login flow with explicit investor and operator surfaces, then verify role journeys against the live backend.
- **Why:** `blockxone` already has persona-specific routes, but sprint-built public and auth entry points still mix investor onboarding with privileged staff access.
- **Output:** A clearer, safer frontend architecture with separate login paths, aligned layouts, and evidence-backed route journeys.

## UI Direction

- Landing pattern: enterprise gateway with explicit investor and operator choices
- Operator shell: data-dense dashboard language, fast scanability, SVG iconography, and operational status visibility
- Investor shell: calmer onboarding-first hierarchy with clear KYC and portfolio progression
- Design-system guardrails: semantic color tokens, no emoji icons, visible focus states, and mobile-safe spacing

## Verification

Run:
- `npm run build` in `apps/web`
- Role-specific localhost walkthroughs starting from `/`, `/login/investor`, and `/login/operator`
- Scripted verification for login, logout, redirect, and session restoration across investor and operator roles
- Any available frontend smoke tests that prove investor and operator first-run journeys against API `8080`

## Success Criteria

- [ ] Investor and operator have separate public entry and auth paths.
- [ ] Investor onboarding no longer appears in privileged operator login surfaces.
- [ ] Navigation and layout are coherent within each product surface.
- [ ] Role journeys are verified against the running backend with repeatable evidence.
