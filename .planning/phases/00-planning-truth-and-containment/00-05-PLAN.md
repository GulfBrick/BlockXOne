# Plan 00-05: Generation 3 summary-semantics remediation

## Objective

Resolve the deterministic conflict between the required
`00-04-SUMMARY.md` implementation-freeze record and the pinned GSD tools'
filename-only completion counters, without marking Phase 0 or any requirement
complete and without weakening the complete local test contract.

Approval does not authorize a push, remote, deployment, RPC, provider, wallet,

## Confirmed root cause

The pinned GSD tools apply two different filesystem-derived meanings:

1. `init milestone-op` increments `completed_phases` when any filename in a
   phase directory ends in `-SUMMARY.md`; it never reads summary content.
2. `roadmap analyze` compares summary count with plan count. With this new
   plan present there are exactly five Phase 0 plans. No summary means
   `planned` and artifact ratio `0%`; exactly `00-04-SUMMARY.md` means
   `partial` and artifact ratio `20%`.

Those values are artifact counters. Authoritative production completion remains
defined by STATE, ROADMAP checkboxes/status and REQUIREMENTS checkboxes.

No content-only change to the five Task 6 evidence paths can resolve the old
validator contradiction. This plan therefore authorizes the validator itself
and no other script.

## Narrow supersession

This plan supersedes only these Plan 00-04 statements:

- `progress.total_plans: 4` becomes `5`; and
- Task 6's five-file commit becomes one six-file I3 commit containing the
  validator plus the same five evidence paths.

Every other Plan 00-04 control, immutable boundary, task result, blocker,
non-claim, role-separation rule, I3/R3/V3 ancestry rule and final NO-GO status
remains binding. ROADMAP, REQUIREMENTS, global GSD tools and Plan 00-04 are
immutable.

The Generation 3 repository allowlist is the union of Plan 00-04 and this
plan's `files_modified` lists. No `00-05-SUMMARY.md` may be created because
this is a superseding boundary plan, not Phase 0 completion.
