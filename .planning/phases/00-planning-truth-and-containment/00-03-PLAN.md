# Plan 00-03: Fail-Closed Feature and Delivery Containment

## Objective

Make the production target unmistakably fail closed: unsupported/demo features cannot be reached, mock/dev/raw-key/default modes cannot start as production, and mandatory build/test/security/deploy commands cannot report false success.

## In scope

- feature allowlist and environment-mode validation;
- production configuration and Compose validity;
- CI/test/security exit-code behavior;
- frontend test harness and critical smoke tests;
- contract/web Node version enforcement;
- deploy workflow placeholders converted to blockers or real verified steps;
- documented production no-go route policy.

## Tasks

1. Inventory every mock/dev/demo/default/raw-key behavior reachable from production configuration.
2. Add environment-aware startup validation and negative tests.
3. Correct production Compose schema and require critical values.
4. Remove fail-open security/test flags from mandatory CI paths.
5. Add frontend test configuration and critical public/auth/state smoke tests.
6. Pin/enforce supported Node versions in developer and CI commands.
7. Make deployment workflow fail until migration/deploy/health steps are real and verified.
8. Disable or explicitly gate marketplace/P2P and other excluded release-one routes.
9. Re-run all Phase 0 commands from the clean worktree.
10. Reject prohibited environment, key, archive and binary paths in both the working tree and all history reachable from the candidate.
11. Exercise migrations against clean and current schemas in CI and ensure the runtime image contains migration files.
12. Require explicit local-only seed opt-in, isolate worker credentials and scan reachable Go dependency vulnerabilities.

## Working-tree implementation status

- Production config, API routes and web routes now fail closed for the tested release-one exclusions.
- Toolchains, tests, scans, Compose policy, migration smoke jobs, Docker context exclusions and deployment/rollback blockers are implemented locally.
- The seed command requires explicit `APP_ENV=dev`, `ALLOW_DEV_SEED=true` and a loopback PostgreSQL target.
- The outbox worker receives only production database and NATS configuration.
- This plan remains open because the current ancestry fails the repository-history validator and hosted exact-clean-commit image/race/migration/full-CI evidence does not exist. The contract full audit is locally green through tested exact patched overrides.

## Acceptance

- Production config refuses every tested mock/dev/default/raw-key case.
- Production Compose validates cleanly with an example non-secret configuration contract.
- A deliberately failing security/test/deploy step fails CI.
- Frontend suite contains real tests and returns success only when they pass.
- Go, web build/tests and contract tests use supported pinned toolchains.
- Excluded production routes are unreachable or visibly non-transactional under a server-enforced feature policy.
- No new secret, credential or personal data is committed.

Acceptance is evaluated only on an approved clean-root exact commit. Passing working-tree checks on the contaminated lineage is remediation evidence, not Phase 0 exit evidence.

## Evidence

- Configuration negative-test matrix.
- CI mutation results.
- Clean toolchain/test logs.
- Route/feature-policy tests.
- independent security/adversarial review.

## Rollback

All containment changes use configuration/schema/code commits on the Phase 0 branch. Revert the specific packet commit; never restore unsafe production defaults.
